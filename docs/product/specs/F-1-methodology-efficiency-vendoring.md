# F-1 — Publish methodology execution efficiency

## Why

The accepted maintained-source change reduces routine execution context and clarifies scheduling,
handoff, validation, integration, and assessment. The public install bundle must receive that exact
accepted behavior without changing models, persona permissions, installation, or project adoption.

## Scope

**In:** exact vendoring of the accepted execution and persona routes, their atomic tests, assessment
reference, and an honest public README update.

**Out:** model changes, persona-source changes, new telemetry or schedulers, global installation,
project adoption, publication or merge, hosted CI, and pilot work.

## Acceptance criteria

**AC-1** When the public routes are vendored, given the accepted source manifest, complete controller and reviewer routes remain smaller and name every required owner.

**AC-2** When a persona is selected, given routine routing work, selection stays in the entrypoint and authoring history remains explicitly routed.

**AC-3** When execution policy is vendored, given every existing control applies, approval, safety, judge, lane, evidence, stop, runtime, and stage owners remain explicit.

**AC-4** When a writer hands work back, given uncertainty or incomplete evidence exists, the handoff uses bounded evidence fields without scores, extra judges, or self-acceptance.

**AC-5** When source compatibility is checked, given overlays and unmanaged files exist, accepted source bytes and preview behavior remain compatible without touching external state.

**AC-6** When execution is assessed, given existing records contain joined identifiers, assessment preserves unknowns and keeps usage and cash units separate.

**AC-7** When the public milestone completes, given public and maintained-source persona variants differ, models, efforts, permissions, persona sources, and the five known public variants remain unchanged.

**AC-8** When validation evidence is reused, given its source, command, runtime, and environment inputs remain valid, no redundant rerun is performed.

**AC-9** When the milestone advances, given an accepted slice exists, it uses an authorized commit and write-set check before the final integrated gate.

**AC-10** When unrelated drift is observed, given it is outside this feature, installation, adoption, plugin, pilot, and model findings remain classified outside scope.

## Horizontals

- **Authorization:** source acceptance, public preparation, publication, merge, installation, and adoption remain separate decisions.
- **Audit:** source commit/tree, file hashes, task commits, gate receipt, and acceptance bind one evidence chain.
- **Runtime cost:** context comparisons use words and bytes only.
