# M2 — Carry an approved product goal to validated closure

## Goal

The approved core workflow carries one coherent milestone batch from closed requirements through
delegated implementation, causal recovery and real local validation to a fresh seal and independent
acceptance, then uses existing guarded publication only when its conditional grant still applies.

## Why now

The retired native-first proof approach consumed the delivery path without implementing the core
workflow. M2 returns effort to the approved business outcome while retaining real local gates,
independent judges, failure lineage and founder authority.

## Success criteria

- Requirements, founder interview and context close before dependent design and planning. Where UX
  applies, a separate founder-approved journey is authoritative for its states and behavior.
- The chief owns ready selection, delegation, review, validation and recovery until closure. Valid
  authorization persists across sessions and has no arbitrary time expiry.
- Ordinary work remains Light. Full is reserved for a real durable or safety change.
- Recovery preserves the same cause across renamed attempts. A and B precede a targeted council and
  fresh independent replan PASS before C; C failure ends automatic recovery.
- Existing overengineering questions are asked at the recovery or handoff boundary without adding
  workflow machinery.
- Gate verdict propagation and seal freshness fail closed on nonpass, mutation, stale or mismatched
  evidence.
- Accepted maintained bytes project consistently to the public package and are exposed through the
  existing installer without changing consumer bindings.
- The complete local gate passes, the unchanged candidate is sealed, and fresh acceptance judges
  that candidate before conditional push, pull request or merge. Tag and deployment remain out.
- The one-week review uses existing evidence to assess accepted business value and quality and adds
  no pilot or apparatus.

## Cross-feature validation

| journey | crosses | proves |
| --- | --- | --- |
| J-1 Core delivery | closed requirements and UX authority → ready work → review and validation | The chief can carry approved work without routine reapproval. |
| J-2 Causal recovery | failed correction → preserved cause → A/B → reviewed C or founder stop | Recovery changes the approach without erasing evidence. |
| J-3 Valid closure | maintained source → public package → existing installer → full gate → seal → acceptance | Closure rests on fresh, consistent local evidence. |

## Exit

M2 closes only when all three journeys pass on the same accepted candidate and any publication
uses the existing guarded path under its still-valid conditional grant. A concrete resource,
authority or safety blocker is an honest terminal result; passing partial or synthetic proof is not.
