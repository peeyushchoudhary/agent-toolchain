# Discuss and apply an upgrade

Compare the project's approved identity, installed source and candidate at exact Git referents.
Reconcile source fixes and private operator records before preparing a candidate; a public copy does
not supersede unmerged maintained-source improvements. Preserve existing project overlays and
report compatibility and machine-global impact across adopted projects.

Present the behavioral delta, affected files/projects, evidence, expected benefit and recommended
action: adopt, retain or defer. Current valid execution continues while an optional upgrade is
discussed. A missing dependency or invalid current runtime is a repair/readiness problem, not merely
an optional upgrade notice.

Persona/model changes stay owned by agent-personas. Compare representative tasks under fixed
inputs, criteria and effort controls using actual quality, failure/rework, latency and available
usage/cost evidence. Verify provider support from current authoritative documentation when making a
new recommendation. Do not rerun model research on ordinary tasks or silently switch assignments.

After authorization, test the reconciled candidate in an isolated binding, verify owning suites and
real workflow fixtures, then stage the scoped installation/adoption. Obtain write-equivalent JSON
previews from each affected owner with explicit `--scope project`, `--scope global`, or
`--scope all`; never infer global scope from a repository argument. Preserve unmanaged
configuration and record rollback referents. Update README/routes and publish source/private
backups only through authorized PR actions. Global install, project adoption, model activation and
deployment are separate outcomes and must be reported accurately.
